# Caltrain — CalHacks

A Caltrain rider app for iOS and Android: live departures, trip planning with
arrival estimates and fares, upcoming-stop notifications, and a live map.

Built with [Expo](https://expo.dev) (React Native + TypeScript, Expo Router) on
top of the [511 SF Bay](https://511.org/open-data/transit) GTFS static and
GTFS-Realtime feeds for Caltrain.

## Features

| Screen       | What it does                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------- |
| **Schedule** | Next departures from any station (defaults to the nearest one), merged with live predictions.   |
| **Plan**     | Origin → destination planner. "Leave now" or "Arrive by", with realtime delay and the fare.      |
| **Map**      | Line alignment, all stations, and live train positions.                                        |
| **Trip**     | Tap any train: every stop with scheduled + predicted times, and a 🔔 to get a stop alert.      |

## Getting started

```bash
cp .env.example .env          # then paste your 511 API key
npm install
npm run gtfs                  # download the GTFS static feed → data/*.json
npx expo start                # scan the QR with Expo Go
```

Get a free 511 key at <https://511.org/open-data/token>. Keys are limited to
60 requests per hour, so the app polls each realtime feed once a minute.

### Useful commands

```bash
npm run gtfs          # regenerate bundled schedule (re-run when Caltrain publishes a new timetable)
npm run typecheck     # tsc --noEmit
npm run lint          # expo lint
npx expo run:ios      # development build (needed for react-native-maps on Android, optional on iOS)
```

## Project layout

```
app/                    Expo Router screens
  (tabs)/index.tsx      Schedule
  (tabs)/plan.tsx       Trip planner
  (tabs)/map.tsx        Map
  trip/[tripId].tsx     Trip detail + stop alerts
components/             Shared UI (StationPicker, RouteBadge, DelayText, …)
hooks/                  usePolling, useLiveData (511 feeds), useNow, useNearestStation
lib/
  api/                  511 clients: StopMonitoring, TripUpdates, VehiclePositions
  gtfs/                 Bundled-schedule accessors, service calendar, planner, fares
  notifications.ts      Upcoming-stop local notifications
  storage.ts            AsyncStorage for stop alerts
data/                   Generated by scripts/build-gtfs.mjs (schedule, stations, fares, shape)
scripts/build-gtfs.mjs  GTFS static → compact JSON
docs/                   Plan and architecture notes
```

## Notes and limits

- Realtime predictions only exist for trains currently running; everything else
  shows the scheduled time and is labeled "scheduled".
- Stop alerts are local notifications scheduled from the latest prediction at
  the moment you tap the bell. They don't re-adjust if the train's delay changes
  afterwards (a good next step: a background task that reschedules them).
- `EXPO_PUBLIC_*` env vars are inlined into the JS bundle, so the 511 key ships
  with the app. Fine for a hackathon; rotate it before any public release.
